# Fenton Family Pokémon Cards: website

A free, static, phone-first website for the family collection. It's plain HTML/CSS/JS with no build step and no paid services.
It reads one file, `data.json`, which `build_data.py` generates from the box data that the daily price routine already keeps current.

## Where the data comes from
| data.json part | source |
|---|---|
| cards, qty, binder/page/pocket, prices, pictures, TCGplayer links, PSA 10, 30-day baseline | `/workspace/collection/collection.json` (the daily routine keeps it in sync with the sheet's All Cards tab; cards[i] = sheet row i+2) |
| value-over-time chart + per-card ticker history | `/workspace/collection/price_history/YYYY-MM-DD.csv` → `dates`, `history`, `ph` in data.json (today's qty × each day's prices, forward-filled). Home + card charts: **1M / 6M / Lifetime** range buttons. |
| Opened Products | `sheet_cache/opened_products.json` (copy of the 📦 Opened Products tab) |
| set sizes / wishlist flags / release dates | `sheet_cache/sets.json` (copy of Sets & Binders A1:N20) |
| binder names/emoji | `sheet_cache/binders.json` |
| PSA fee tiers, 💎 rules, trend rule (±5% or < $0.25) | `sheet_cache/settings.json` (copy of Sets & Binders P1:R27) |

Trend, PSA gain and verdict use the same formulas as the sheet (cols AD, Y, AE). `python3 build_data.py --check` prints the totals.
On 2026-10-18 they matched the sheet: $1,114.38 · 354 cards · 205 different · ➕5 ➖75 ⏸️125 · 30th 141/158 · Classic 12/30 · wishlist 35 / $827.83 · 106 packs.

The site does NOT read the Google Sheet live. That would need the sheet to be public, and its sharing settings are left unchanged.

### Sheet data (sheet_cache)
Only update these when those tabs change, e.g. a new opened product, a new set or binder, or new PSA fees. Use the Google Sheets connector
(`user-Google-sheets` → `read_range`, spreadsheetId `1U-bajlW6HKeB_tzBhZfsQRhAcV8quHtBd99D8MZCfco`):
- `'📦 Opened Products'!A4:J23`: B product, C set, D qty, E packs each, G notes, H price, J TCGplayer URL → `opened_products.json` keys
  (L = list price each, US MSRP → `msrp`; build_data totals.spent_msrp = Σ qty × msrp)
  `product,set,qty,packs_each,note,price,url`
- `'Sets & Binders'!A1:N20` → `sets.json` (`name,code,api,size,wishlist,released`; add `"order":"binder"` to keep photo/binder order instead of number order)
- `'Sets & Binders'!A23:F40` → `binders.json` (`name,emoji,desc,pages`). A binder only appears on the site if it's listed here.
- `'Sets & Binders'!P1:R27` → `settings.json`
New cards and new binder pages need no cache change. They come in through collection.json.

## Daily: regenerate + republish (add to the daily price-refresh routine, after steps 1-7 in sheet_info.txt)
```bash
cd /workspace/site
python3 build_data.py --check                     # rewrites data.json from collection.json + price_history
git add -A && git commit -q -m "Prices $(date +%F)" && git push -q   # only once a host is set up (below); skip if "nothing to commit"
```
Cloudflare Pages instead of GitHub:  `npx wrangler pages deploy /workspace/site --project-name fenton-pokemon --branch main`

Phones pick up the new data the next time the site is opened. data.json is fetched network-first, and the cached copy is used offline.
If you change index.html/app.js/style.css, bump `VERSION` in sw.js so installed phones drop the old cache.

## Grading & value
`#/grading` compares raw vs PSA 8/9/10 and TAG 9 / Gem 10 / Pristine for cards we own. Medians need at least 5 matching sales (changeable under Assumptions). Thinner grades stay as individual sales. Missing prices stay unknown. The page does not compute an expected value and does not refresh prices.

The bundled rows are the cross-checked 2026-11-07 file. They reproduce reported eBay and TCGplayer sales. They are not independently verified, shipping is unknown, and accepted offers are unverified. The same eBay item is counted once.

Fee defaults are dated 2026-11-07 (TAG Standard article dated 2026-10-21) and can be edited in the browser. `data.json` is unchanged, including its older sheet PSA formula.

The page is public, the same as the rest of the site. It is not a private tab. Grading notes and imports stay in browser keys that start with `fenton.grading.` and end in `.v1`. Those saves do not read or remove collection keys such as `fg.trainers` or `moversSort`. There is no button that deletes storage. Replacing grading settings with the published defaults, or stopping the use of saved sales, first copies the current grading keys into `fenton.grading.backup.v1`. Imports are capped at 500 rows and 400000 characters. CSV export prefixes cells that start with `=`, `+`, `-`, `@`, or a tab so a spreadsheet does not run them as formulas.

## One-time publishing (free)
**GitHub Pages** (free accounts need a public repo):
```bash
gh auth login                                   # Stephen signs in once (browser/device code)
cd /workspace/site && git init -b main 2>/dev/null; git add -A && git commit -m "Pokémon site"
gh repo create fenton-pokemon --public --source=. --push
gh api -X POST "repos/$(gh api user -q .login)/fenton-pokemon/pages" -f "source[branch]=main" -f "source[path]=/"
# site: https://<github-username>.github.io/fenton-pokemon/  (first deploy takes ~1 minute)
```
**Cloudflare Pages** (the project can be private): `npx wrangler login`, then the deploy command above → `https://fenton-pokemon.pages.dev`.

**Privacy:** a public URL shows the card list, binder layout and values to anyone who has the link. `robots.txt` and `noindex` keep it out of search engines.
Names, emails and addresses are not in the site. The newsletter recipients are kept out of every file here.

## Images
Card pictures load straight from TCGplayer's CDN (`https://tcgplayer-cdn.tcgplayer.com/product/<id>_200w.jpg`, 400w in the card pop-up).
The service worker caches the pictures you've viewed so they work offline.
